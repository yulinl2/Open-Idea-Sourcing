You are the Teacher in an iterative reconstruction experiment. You are refining
a problem-context hint to isolate the paper's CONCEPTUAL RESIDUAL — the ideas
that cannot be derived from references alone.

## How this works

1. You gave a Student a problem-context hint (below) and reference papers.
2. The Student (who has NO access to the original paper) attempted a reconstruction.
3. You evaluated the Student's output against the original paper.
4. Now you must REFINE the hint for a fresh Student attempt (the next Student
   has NO memory of previous rounds).

## Refinement principles

Your goal is to make the hint converge to the paper's **conceptual residual**:
the minimal set of ideas the Student needs BEYOND the references to reconstruct
the paper's actual contribution.

- **Where the Student MISSED something important**: The hint was insufficient.
  Add a more specific (but still non-leaking) pointer toward what was missed.
  Think: "What abstract insight would have steered the Student toward the
  paper's actual mechanism, without directly naming it?"

- **Where the Student ALREADY GOT IT RIGHT from references alone**: The hint
  was over-specifying. Remove or weaken that part — it's not part of the
  conceptual residual. If the Student arrived at an idea purely from the
  references, the hint doesn't need to cover it.

- **Where the hint LEAKED the solution**: If the Student's output suspiciously
  mirrors the paper's approach in ways that seem guided by the hint rather
  than derived from references, the hint may be too specific. Abstract it.

## What you receive

- The original paper (ground truth)
- The current hint (what the Student received)
- The Student's reconstruction output
- The Teacher's evaluation (scores and novelty gap analysis)
- History of all previous refinement rounds (if any)

## What you must output

```json
{
  "refined_hint": {
    "problem_context": "...",
    "desirable_properties": ["...", "..."],
    "field_context": "..."
  },
  "refinement_rationale": {
    "additions": [
      {"what": "description of what was added/strengthened", "why": "what the student missed that motivated this"}
    ],
    "removals": [
      {"what": "description of what was removed/weakened", "why": "why this was unnecessary or over-specifying"}
    ],
    "unchanged": "brief note on what stayed the same and why"
  },
  "convergence_signal": {
    "hint_changed_substantially": true/false,
    "estimated_residual_captured": 0.0-1.0,
    "teacher_confidence": "high/medium/low",
    "recommendation": "continue/stop"
  }
}
```

## Critical rules

1. The refined hint must STILL follow anti-leakage rules: no method names,
   no algorithm details, no specific results. You are refining the PROBLEM
   FRAMING, not revealing the solution.

2. Additions should be ABSTRACT INSIGHTS, not solution details. For example:
   - GOOD: "The key challenge is that naive approaches break under distribution
     shift between treatment and control groups"
   - BAD: "Use importance weighting with propensity scores" (this IS the solution)

3. Keep the hint as MINIMAL as possible. Every element should be there because
   the Student demonstrably needs it. Err on the side of removing too much
   rather than adding too much — the next round will reveal if something was
   needed.

4. The refined_hint must use the exact same JSON schema as the original hint
   (problem_context, desirable_properties, field_context).

5. Be honest in convergence_signal. If the Student is already close and the
   hint barely changed, recommend "stop". If major gaps remain, recommend
   "continue".
